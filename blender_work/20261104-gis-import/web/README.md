# 세종·서울 웹 3D 작업 기록

> 아래 기존 `v5` 경로는 이관 전 작업 이력이다. 현재 생성·검증 명령과 안전한 출력은 [재생성 절차](../REPRODUCTION.md)를 따른다.

## 결과와 실행

v5의 `/visit/area/`에서 광화문 주변과 서울 전역을 전환한다. 기본은 세종문화회관 주변이다. 서울 모드는 광화문 상세 모형을 같은 좌표에 함께 두고, 그 부지와 겹치는 서울 격자만 가린다. 확대·축소·좌우 회전·처음 보기 버튼은 키보드로도 사용할 수 있다. 마우스·터치 드래그로 회전할 수 있으며 서울 데이터는 서울 버튼을 처음 누를 때만 가져온다.

로컬 실행은 `v5`에서 `npm.cmd run dev -- -p 3137` 후 `http://localhost:3137/v5/visit/area/`를 연다. 정적 결과는 루트에서 HTTP 서버를 띄운 뒤 `/v5/visit/area/`로 접근한다. WebGL이 필요하며 로딩 실패 시 화면에 재시도 버튼을 표시한다.

## 원본과 생성 과정

1. `gis-sejong/sejong_surroundings_gis_work.blend`를 `sejong_web_source.blend`로 복사했다. 원본과 복사본 SHA-256은 생성 시 일치했다. 원본은 수정하지 않았다.
2. `export_sejong.py`를 Blender 5.2 백그라운드에서 실행해 표시 중인 메시와 간판을 GLB로 내보냈다. 보관·숨김 및 GIS 비교 윤곽은 제외했고, GIS 서쪽 건물 28개와 남쪽 건물 4개를 포함했다. 간판 5개는 메모리에서 메시로 바꿔 내보냈다. 11개 이미지는 GLB 내부에 들어 있다. 메시 압축은 EXT_meshopt_compression, 좌표 필터 정밀도 23비트다.
3. `export_city.py`는 `gis-sejong/seoul/seoul-grid-50m.json.gz`에서 브라우저에 필요한 위치·평균 높이·높이 근거 구분만 추출해 `v5/public/area/seoul-grid.json`을 만든다. 좌표 123,626개는 중복 없이 보존한다. 원본의 695,753건 중 좌표 이상치 2건을 제외한 695,751건을 집계한 자료다.
4. `AreaViewport`는 GLB를 표시하고, 서울 모드에서만 3개의 `InstancedMesh`로 격자를 생성한다. 기본 화면이 서울 데이터 2.47MB를 먼저 내려받지 않도록 한다. 화면 밖으로 전환되면 GPU 자원과 이벤트를 정리한다.

회관 로컬은 Blender X=N−552531, Y=197897−E, Z=높이이고 glTF로 바뀐 축은 `(X,Z,−Y)`다. 서울은 Three 좌표 `(E−200000, 높이, 550000−N)`을 사용한다. 따라서 서울 장면의 회관은 Y축 +90도, 위치 `(-2103, 0, -2531)`로 배치한다. 상세 모형의 기초 외곽에 해당하는 서울 셀 중심 X `[-2303,-1843]`, Z `[-2771,-2321]`는 중복을 피하려고 숨긴다. 이 정합은 기존 사진 추정 모델에 맞춘 근사치다.

## 표시 범위와 한계

광화문 주변은 현장 사진과 GIS에서 만든 모형으로, 위치와 건물 높이에는 추정이 있다. 동쪽 GIS 건물 윤곽은 기존 장면의 도로·보도와 어긋나 아직 확정 배치하지 않았다. 서울 화면의 기둥은 50m 셀의 건물 높이 평균을 나타내는 **개요**다. 개별 건물 외형이나 행정 경계, 실제 강·도로·지형이 아니다. 높이 후보가 없을 때 층수 추정 또는 3.2m 표시값을 사용한다. 노란 원은 회관 위치를 찾기 위한 표시다.

사용자 로컬 GIS 사본의 출처와 필드 정의는 확인되지 않았다. 유사한 국토교통부 [GIS건물통합정보 메타데이터](https://www.data.go.kr/catalog/15083092/fileData.json)는 출처 표시 조건을 기재한다. 기존 세종 모형의 사진·자료에 대한 출처와 추정 경계는 상위 `gis-sejong/README.md` 및 `gis-sejong/seoul/README.md`를 참고한다.

## 검증 기록

- GLB의 1,235개 표시 노드, 내장 이미지 11개, 서쪽 28개·남쪽 4개 GIS 매스와 meshopt 확장을 확인했다.
- 좌표 변환과 상세 영역 제외 규칙은 `node --test v5/tests/area-coordinates.test.ts`로 확인한다.
- 브라우저 검사는 `v5`에서 `node tests/area-browser.cjs`로 실행한다. 광화문 초기 로딩, 서울 지연 로딩·전환, 회전·확대·초기화, 390px 화면, 요청 실패와 재시도를 검사한다. Chromium의 소프트웨어 WebGL을 사용한 검사이며 물리 모바일 기기의 성능을 보장하지 않는다.
- 시각 확인: `evidence-local.png`, `evidence-seoul.png`, `evidence-mobile-initial.png`, `evidence-mobile-seoul.png`.

### 이번 실행 결과

- 공개 콘텐츠 DB 환경이 빠진 첫 빌드는 사전 단계에서 중단됐다. 연결된 프로젝트의 공개 설정을 사용해 기존 실패 폐쇄 규칙을 유지한 채 다시 빌드했으며, 공개 콘텐츠 스냅샷은 변경되지 않았다. 최종 `npm run build`는 정적 페이지 162개 생성과 `sync-out`까지 성공했다.
- 독립 검토에서 GLB 실패 뒤 범위 전환 시 재시도 상태가 사라지는 문제를 찾았다. `area-glb-failure.cjs`로 실패를 재현한 뒤 오류 상태를 유지하도록 수정했고, 범위 전환과 재시도 성공을 확인했다.
- 정적 HTTP 서버의 실제 출력에서 `area-browser.cjs`와 `area-glb-failure.cjs`가 통과했다. 전체 메뉴를 열어 `/v5/visit/area/` 링크를 확인했다. 데스크톱과 390px의 두 범위를 이미지로 확인했다.
- 루트 및 v2·v5 Node 테스트 109개가 통과했다. 정식 빌드는 기존 CSS의 autoprefixer 경고를 출력했으나 종료 코드는 0이었다. 서비스 배포나 실제 모바일 기기 성능은 이번 검증 범위가 아니다.

## 건물 정보와 전시천리안 (2026-11-04)

돋보기는 광화문 상세 모형 또는 서울 격자에서 선택한 위치 주변의 원본 건물 폴리곤을 조회한다. 서울 격자는 50m 평균이므로 클릭 위치와 개별 건물의 실제 위치가 어긋날 수 있다. 원본에 없는 주소·속성은 `미기재`로 표시하며, 주소는 도로명 주소가 아닌 법정동과 지번을 조합한 것이다. 모든 원본 29개 필드는 선택 결과에서 확인할 수 있다.

전시천리안은 서울 자료 695,753건의 위치를 GPU 점으로 투사한다. 좌표 이상치 2건은 서울 화면 범위 밖에 있다. 광화문 화면은 그 지역의 점만 표시하며, 겹침을 줄이기 위해 읽을 수 있는 가까운 건물의 이름·주소·용도·높이·층수만 최대 25개 레이블로 표시한다. 나머지 필드는 아래 목록에서 확인한다. 664개 지역의 전체 목록을 페이지로 둘러보거나 서울 전체 주소·이름을 검색할 수 있다. 검색 결과는 최대 200건이므로 필요하면 검색어를 구체화한다. 데이터 생성·출처·검증 세부 사항은 `BUILDING-DATA.md`에 기록했다.

## 서울 시각과 하늘

웹 하늘은 브라우저 시계를 서울 시간으로 해석해 NOAA 태양 위치 계산으로 매 분 갱신하며, 낮·밤 조명과 하늘을 바꾼다. 실시간 기상 관측이나 구름은 반영하지 않는다. 저장소의 세 Blender 파일은 24시간 조명 키프레임과 서울 시각 갱신 스크립트를 포함한다. Blender를 다시 연 뒤 실시간 갱신을 시작하려면 내장 텍스트 `Seoul live sky.py`를 실행해야 한다. 보안 설정을 전역으로 바꾸지 않는다. Blender 적용과 재현 절차는 `../sky/README.md`를 참고한다.

## 추가 검증

`node --test v5/tests/area-buildings.test.ts v5/tests/area-solar.test.ts v5/tests/area-coordinates.test.ts`는 좌표·폴리곤·서울 태양 위치를 검사한다. `v5`의 `node tests/area-inspection.cjs`, `node tests/area-race.cjs`, `node tests/area-sky-browser.cjs`는 각각 도구와 전체 검색, 늦게 도착한 선택 응답, 서울 낮과 밤을 검사한다. 정적 출력이나 배포 검사는 `AREA_TEST_ORIGIN`을 대상 원점으로 지정한다. Chromium 소프트웨어 WebGL 결과이며 실제 모바일 기기 성능을 보장하지 않는다.

2026-11-04 최종 변경에서 전체 Node 검사 114개와 390px 메타데이터 화면 검사가 통과했다. 처음 정적 빌드는 개발 서버와 `.next`를 동시에 사용하여 생성 파일 충돌로 실패했고, 개발 서버를 종료한 후 162개 페이지 생성과 타입 검사에 성공했다. 상세 모형과 서울 격자를 함께 클릭 판정하고 비동기 검색·조회 결과의 순서를 보호하도록 독립 검토 의견을 반영했다. 소프트웨어 WebGL의 서울 격자 클릭은 약 1.2초였으며 실제 기기 속도는 별도 확인이 필요하다.

운영 배포 후 실제 도메인에서 느린 타일 응답과 서울 모드 전환이 겹치면 자동 중심 조회가 돋보기 클릭 결과를 덮는 현상을 발견했다. 클릭 조회가 진행되는 동안 자동 조회를 대기시키고 선택 결과를 유지하도록 고쳤으며, 타일 응답에 1.8초 지연을 주는 브라우저 검사로 확인했다.
