# 2026-11-24 거리 기반 장식 렌더링

이전 공간 스트리밍은 멀리 간 청크의 다운로드를 취소하고, 캐시에 붙은 청크는 화면 거리보다 넉넉한 유지 범위에 있는 동안 그렸다. 그래서 건물 주변을 확대해 장식을 한 번 본 후, 회전 중심은 그대로 둔 채 뒤로 멀어지면 가까이에서만 의미 있는 장식도 계속 GPU에 제출됐다.

## 변경

- 스트리밍 manifest의 선택적 `renderDistance`는 실제 카메라에서 청크 3D bounds의 가장 가까운 면까지 잰 거리다. 카페 벽타일·노란 상가 장식은 70m, 주변 동측 입면 장식 네 청크는 125m를 사용한다.
- 경계를 벗어나면 렌더와 그림자를 끈다. 다시 표시할 때는 설정값의 85% 이내(각각 59.5m·106.25m)까지 들어와야 화면에 올라온다. 경계 부근 진동은 렌더 상태를 반복 변경하지 않는다.
- 로딩·재시도·취소와 실제 퇴거 규칙은 유지한다. 숨겨진 자산을 기존 캐시에 둬, 20초 유지 정책이 해제하기 전 다시 가까이 오면 다시 받지 않는다. 잠깐 숨겼다고 GPU 메모리를 반환하는 기능은 아니다.
- 본관 실루엣이 들어 있는 core와 충돌, 보행·계단·테라스·카페 실내·정원은 변경하지 않았다. 거리 정책을 명시하지 않은 자산은 종전대로 동작한다. 숨긴 그룹은 기존 선택 검사에 따라 궤도 더블클릭 대상을 가로채지 않는다.

## 검증

- `node --test tests/modelStreaming.test.js tests/orbitFocus.test.js`: 15개 통과. 거리 옵션의 사전 로드·비표시·경계 왕복·그림자 복귀·캐시 재사용과 비옵트인 표면 보존을 확인했다. 초기 두 신규 테스트에는 이전 동작으로 실패를 먼저 재현했다.
- `npm ci` 및 `npm run build`: Vite의 87개 모듈 빌드 통과. 로컬에서는 원격 소스 그래프와 시험용 GLB를 받아 검증했으며, 전체 대형 공용 자산을 복제하지는 않았다. 기존 500kB 번들 경고는 이번 변경 범위 밖이다.

### 기존/변경 동일 조건 WebGL 비교

로컬 Chromium SwiftShader, 1280×720, Three.js와 Meshopt를 동일하게 사용했다. 실제 배포 GLB 다섯 개를 각각 독립적인 장면에서 비교하고 `renderer.info.render`로 장식 레이어의 호출/삼각형을 기록했다. GLB 단독으로 초점을 bounds 중심에 고정하고 Z 방향으로 36m 근접 → 설정 +22m 원거리 → 설정 −3m 경계 복귀 → 36m 재접근했다. 이는 한 카메라의 전체 장면 합계나 FPS가 아니라, 다섯 독립 시나리오의 절감량이다.

| 실제 청크 | 원거리 전 → 후: draw call | 원거리 전 → 후: 삼각형 |
| --- | ---: | ---: |
| 동측 대사관 입면 장식 | 16 → 0 | 1,440 → 0 |
| 동측 KT 입면 장식 | 18 → 0 | 1,188 → 0 |
| 동측 교보 입면 장식 | 6 → 0 | 960 → 0 |
| 동측 박물관 입면 장식 | 16 → 0 | 1,632 → 0 |
| 노란 상가 장식 | 8 → 0 | 2,124 → 0 |

근접 및 재접근에서는 전후가 다섯 시나리오 모두 같았다. 각 시나리오의 스트리밍 로드 호출은 전후 1회였다. 로컬 픽스처에서는 브라우저가 동일 모델을 한 번 읽은 뒤 두 정책에 각각 제공하므로 HTTP 전송량 비교는 아니다. 카페 타일은 전송 제약으로 브라우저 자산 비교에 포함하지 않았으며 공통 경계 동작은 단위 테스트로 확인했다. 실측 FPS, 생산 네트워크, 전체 캠퍼스 렌더링은 이 비교에 포함되지 않는다.
