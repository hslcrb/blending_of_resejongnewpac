# 대극장 내부 체험 구현 계획

**목표:** 제공된 로비·객석·무대 사진과 1층 약도를 바탕으로, 로비에서 객석과 무대 뒤편까지 걷고 앉아 영상과 공간 음향을 경험한다.

**구조:** 기존 외부 3D·GIS 서비스에서 별도 내부 체험으로 진입한다. 사진에서 확인되는 내부는 독립 Blender 사본과 GLB를 사용하고, 1층 로비는 같은 좌표계의 웹 장면으로 연결한다. 영상 텍스처와 헤드폰 HRTF 공간음향은 사용자 조작으로 시작하며, 선택한 무대효과는 영상 진행과 함께 변한다. 서울의 날짜·시간과 관측 기반 하늘은 기존 웹에서 유지하고 주간·야간 가시성을 개선한다.

**자료와 한계:** 사진은 형상·색상 참고용이다. 사진에 없는 공간과 정확한 무대 장치 치수는 확인할 수 없으므로 사용자가 요청한 뒤편 이동을 위한 가상 구성으로 구분한다. 제공 MP4 원본을 보존하고 Pages 파일 크기 한도 안의 웹 사본을 사용한다. 사용자의 QGIS·Blender 원본과 기존 서비스는 보존한다.

**인터페이스:** 대극장 모델은 X 좌우, Y 높이, Z 객석/로비 방향; 무대 앞 Z=0, 객석 Z=3–27, 백스테이지 Z=-2–-20, 로비 Z=30–43. 모델 제작자가 좌석·막·스크린 이름과 상세 충돌 정보를 제공한다. 영상 모듈은 `createTheatreMedia({THREE,camera,screen,effectLights,onStatus,src})`와 play/pause/setEffects/update/dispose를 제공한다.

- [ ] 독립 Blender 실내와 좌석·커튼·백스테이지 모델을 제작하고 실제 렌더를 사진과 비교한다.
- [ ] 밝은 석재 기둥·청동 장식·격자와 붉은 계단이 있는 로비를 만들고 객석 통로와 이어준다.
- [ ] 키보드·터치 보행, 출입과 좌석 선택/착석·일어서기를 연결하고 충돌과 되돌아가기를 검증한다.
- [ ] 영사 스크린, 브라우저 재생 제어, HRTF 공간음향, 선택형 시간 동기 무대효과와 오류·자원 정리를 구현한다.
- [ ] 실외 조명·낮/밤 하늘을 조정하고 고정 시간의 화면을 비교한다.
- [ ] 원본·사본과 참고 이미지의 출처·현실과의 차이, 사용 방법을 문서화하고 브라우저 데스크톱·모바일, 보행·좌석·영상·날씨, 회귀 테스트와 빌드를 확인한다.
- [ ] 브랜치를 통합해 수시 푸시하고 Cloudflare Pages의 최종 production 커밋을 확인한다.
