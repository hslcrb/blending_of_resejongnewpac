# 전국 후보 위치와 선택 정보 동기화 (2026-11-04)

## 문제와 처리

서울 건물·종로구를 선택한 상태에서 부산 문화시설 후보의 `이 후보의 위치 보기`를 누르면 카메라는 부산으로 이동했지만 기존 서울 건물과 종로구 정보가 남았다. 전국 후보 선택 시 즉시 이전 건물·경계 결과를 지우고, 후보의 대표점 좌표를 새 선택으로 설정한다. 행정경계 조회는 모델·서울 격자 로딩과 독립적으로 새 좌표의 광역권을 불러와 처리한다. 기존 건물 선택, 전국 후보, 수동 돋보기와 서울 건물 검색이 공통 세대 번호를 사용하여 늦은 응답이 후속 선택을 덮지 않도록 한다.

서울 밖 후보에는 `서울 밖 선택 위치에는 서울 건물 자료가 제공되지 않습니다`라고 표시하고 서울 타일을 해당 위치의 전국 자료처럼 조회하지 않는다. 서울 후보는 주변 서울 건물 자료를 조회하며 실패 시 `선택 위치 건물 정보 다시 불러오기`를 제공한다. 주소·코드가 불명확하면 서울 여부를 단정하지 않는다. 직접 돋보기를 사용하는 경우에도 행정경계 조회 결과가 서울 자치구를 포함하지 않으면 서울 건물 자료 범위를 안내한다. 경계 자료가 실패하면 기존 경계 재시도를 통해 같은 선택 위치를 다시 확인할 수 있다.

광화문·서울 보기 전환 또는 사용자의 새 돋보기·서울 검색 선택은 대기 중인 이전 문화시설 카메라 이동과 위치 조회를 무효화한다. 전국 문화시설 후보는 건축물 변경 자료의 대표점이며 실제 출입구와 다를 수 있다. 서울 범위는 선택 후보의 원본 A30 지역코드와 자치구 데이터 기준이며, 실제 관할 변경이나 지적 측량 판정이 아니다.

## 검증

- `node --test tests/location-context-coverage.test.js`: 실제 전국 문화시설 후보 중 지역코드가 확인되는 좌표와 서울 25개 자치구 폴리곤 포함 여부를 대조한다. 2026-11-04 자료에서는 불일치가 없었다.
- `node tests/location-context-browser.cjs`: 세종로 서울 건물을 고른 후 부산 후보를 선택하면 기존 서울 정보가 사라지고 부산 경계가 표시되는지, 부산에서 직접 돋보기를 쓸 때도 서울 밖 안내가 나오는지 확인한다.
- `node tests/location-context-race.cjs`: 지연된 부산→제주 연속 선택, 지연된 부산 경계 응답 후 광화문 수동 돋보기, 지연된 카메라 이동 후 뷰 전환, 지연된 서울 검색 결과 후 부산 후보 선택의 우선순위를 검사한다.
- `node tests/location-context-retry.cjs`: 서울 건물 타일과 부산 행정동 자료를 각각 실패시키고 재시도하며 선택 위치와 독립 경계 정보를 확인한다.
- 최신 main `c8b8850`의 경계 요청 취소 코드와 결합한 테스트를 위해 해당 파일을 원본 수정 없이 개발 서버 응답에 주입했다. 외부 OSM/EOX 타일은 모의 응답해 자동 지도 스캔을 피했다.

Playwright와 Chrome을 사용하며 `PLAYWRIGHT_PATH`, `CHROME_PATH`, `AREA_TEST_ORIGIN`으로 실행 환경을 지정한다. 전체 Node 테스트 83개와 Vite 운영 빌드가 통과했다. 실제 기기 성능과 행정구역의 최신성을 보증하는 검사는 아니다.

기존 서울 검색 결과를 불러오는 동안에는 검색 패널을 유지하고, 실패하면 검색 결과에서 재선택할 수 있다. 기존 서울 검색·29개 필드·664개 지역·페이지·검색 경합·실패 복구 브라우저 검사도 통과했다.
