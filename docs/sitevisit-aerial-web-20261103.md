## 웹용 표면과 GLB

Blender Noise/Bump를 그대로 내보내면 glTF에서 동일하게 보이지 않는 문제를 피하도록, Blender 내부에서 새 계단 석재·카페 외곽 석재·정원 벽돌의 색 무늬를 각각 512px PNG로 EMIT 베이크했다. UV와 표준 PBR ImageTexture로 연결하고 이미지를 pack했다. 원본 사진의 픽셀을 잘라 만든 표면이 아니다. PNG 원본은 `assets/textures/20261103_*.png`에 있다.

보이는 모델 요소 1,330개를 기본 외형과 26개 공간 상세로 한 번씩 분할해 같은 월드 원점에서 내보냈다. Curve와 Font는 내보내기 전용 씬의 메시 프록시로 변환했다. 원본 모델링 객체는 보존했다. 숨긴 독립 연구 씬·이전 archive·베이크 평면과 카메라/조명은 웹 모델에서 제외했다.

독립형 GLB 27개는 `public/model/stream/`에 보존했다. 모든 파일은 Meshopt `EXT_meshopt_compression`을 사용하며 Draco는 사용하지 않았다. 위치 필터 정밀도는 내보내기 동안 23비트로 높이고 기존 기본값으로 복구했다. 기본 모델은 **8,668,108바이트**, 종전 단일 파일은 24,260,732바이트로 기본 모델 다운로드가 약 **64.3% 감소**했다.

[독립형 GLB 검증](sitevisit-review/20261103-glb-verification.md)은 압축 bufferView 2,254개를 실제 해제하고, POSITION accessor 826개/정점 3,467,820개를 읽어 월드 좌표 범위와 이미지 내장을 확인했다. 모든 GLB 내부의 전체 씬/노드와 1,330개 원본 배정이 정확히 일치한다. 초기 검사에서 다른 씬의 보조 평면이 섞인 것을 발견해 `use_active_scene=True`로 전 파일을 다시 내보냈다.

### 수목 형상 공유

독립형 분할 파일의 합계는 55,284,184바이트였다. 동일한 수목 prototype의 압축 형상이 여러 구역에 반복 내장된 것이 큰 원인이었다. 이를 단순히 더 낮은 해상도로 바꾸지 않고 **동일한 GLB 사용처 집합**을 가진 압축 view끼리 묶었다.

- `public/model/stream-shared/`의 12개 최적화 GLB는 내용 해시가 있는 공유 BIN 3개를 참조한다. 나머지 15개 GLB와 기본 모델은 기존 독립형 파일을 그대로 사용한다.
- 모든 구역을 방문했을 때 고유 모델 payload는 **27,601,974바이트**로 줄어, 독립형 합계에서 27,682,210바이트를 절감한다. 구역별 접근 시 필요한 형상만 받으며 기본 모델에는 외부 버퍼 요청이 추가되지 않는다.
- campus 식재 파일은 최대 3개, 새 뒤 정원과 public 식재는 각각 1개 공유 버퍼를 추가로 요청한다. 공유 BIN은 첫 접근 뒤 여러 구역이 재사용한다. 최초 공유 청크에는 GLB를 읽은 뒤 BIN을 받는 요청 단계가 추가되며 네트워크 지연에 따라 차이가 날 수 있다.
- 모든 압축 view와 해제한 93,751,760바이트를 원본과 비교해 **바이트 단위 일치**를 확인했다. 메시 배치·재질·이미지·accessor는 바뀌지 않는다. 사용처가 같은 view를 묶었으므로 alignment 76바이트 외의 형상 overfetch는 없다.

[공유 파일 검증](sitevisit-review/20261103-shared-glb-verification.md)에 실제 GLTFLoader HTTP 로드와 비교 자료가 있다. 최적화 GLB를 수동으로 옮길 때에는 해당 `shared/` BIN도 함께 보존해야 한다. 한 파일로 옮기는 용도라면 `public/model/stream/`의 독립형 GLB를 사용한다.

형상을 바꾸지 않는 재묶기 도구는 다음 명령으로 재실행할 수 있다. 원본 manifest 사본과 독립형 GLB는 보존하며 현재 production manifest를 입력으로 삼아 다시 가공하지 않는다.

```sh
node scripts/deduplicate-stream-geometry.mjs --manifest public/model/stream-shared/source-streaming-manifest.json
```

## 거리별 로딩과 캐시

[웹 공간 로딩 기록](sitevisit-lazy-loading-20261103.md)에 구현과 테스트를 정리했다. 기본 모델이 준비되면 조작을 시작하고, 가까운 상세를 한 파일씩 추가한다. 실제 카메라와 회전 중심의 거리, 화면에서 너무 작게 보이는지까지 함께 판단한다. 멀어진 구역은 그림자를 끄고 숨기며, 20초 이상 멀면 geometry·material·texture와 GPU 인스턴스 자원을 해제한다. 화면 밖이나 숨긴 탭에서는 렌더링을 쉰다.

별관 보행 충돌은 새 깊이에 맞게 늘렸고 legacy 모드의 기존 치수는 유지했다. 늦게 도착한 청크 때문에 회전 중심이나 초기 카메라가 바뀌지 않도록 회관의 focusBounds를 별도로 사용한다.

Cloudflare Pages의 `_headers`로 최신 manifest와 보행 경계는 재검증하고, 내용 해시가 있는 공유 버퍼에만 장기 immutable 캐시를 적용한다. 설정 형식은 [Cloudflare 공식 Headers 문서](https://developers.cloudflare.com/pages/configuration/headers/)를 대조했다. 기존 Git 연동 배포와 두 접속 주소를 유지하며 GitHub Actions 워크플로를 추가하지 않는다.

## 보존 및 확인 범위

기존 Blender 원본·이전 수작업 복사본·독립형 GLB·사진 원본을 보존했다. 새 Blender 파일은 항공 비례 검토 씬을 열어 저장했다. 건물의 사진상 비례, 바이너리/공간 배정, 실제 요청과 웹 조작을 각각 확인하며, 실사 완성도·모든 기기에서의 FPS를 보증하는 것으로 표현하지 않는다.

최종 전체 Node 테스트는 **50개 통과/실패 0개**, production build도 성공했다. [테스트 출력](sitevisit-review/20261103-test-suite.log)과 [빌드 출력](sitevisit-review/20261103-production-build.log)을 보존했다. 첫 JS 묶음은 약 811.6kB이며, GLTFLoader/디코더는 별도 동적 묶음이다. 기존 500kB 초과 번들 안내가 남는다.

실제 웹 검토에서 카페 주변에 넓은 지면이 스스로 그림자를 드리우며 생기는 얼룩을 발견했다. 넓고 낮은 지면은 그림자를 받되 투사에서 제외하고, 석재 벽·지붕·작은 화단 턱은 계속 그림자를 드리우도록 고쳤다. 모형 보기의 거리별 near plane은 밀리미터 마감 간격의 깊이 정밀도를 높이며 직접 걷기에서는 0.1m를 유지한다.

최종 로컬 브라우저에서 `20261103-aerial-shared` manifest를 실제 사용했다. 첫 화면의 GLB 요청 합계는 8,996,484바이트였고 campus/public 식재 GLB와 공유 BIN은 아직 요청하지 않았다. 후면·걷기·계단·카페를 이동한 뒤 공유 BIN의 고유 URI는 정확히 3개였으며, 이전 raw campus 파일 요청과 콘솔 경고/오류는 없었다. [실제 요청 목록](sitevisit-review/20261103-web-streaming-network.json)과 `20261103-web-streaming-*.jpg`에 화면을 보존했다.

마지막 Git 검사에서는 한 압축 BIN의 처음 8,000바이트에 NULL이 없어 Git이 텍스트로 분류하는 것을 발견했다. 스테이징 데이터는 이미 원본과 일치했지만, 바이너리 파일에 대한 공백 검사와 향후 줄바꿈 변환을 막도록 `.gitattributes`에 `.blend`·`.glb`·`.bin`을 명시했다. 다시 스테이징한 모델/미디어의 실제 바이트를 원본 파일과 모두 대조한 결과는 [릴리스 검증](sitevisit-review/20261103-release-verification.json)에 있다.
